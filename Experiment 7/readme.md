# Experiment 7 — Analysis of WPA2 Four-Way Handshake with Wireshark

## Aim

To examine a WPA2 four-way EAPOL handshake using Wireshark and understand the exchange of authentication messages, nonces, MIC values, and replay counters between a wireless access point and a client.

## Overview

WPA2 (Wi-Fi Protected Access 2) is a wireless security protocol used to protect communication between wireless devices and access points.

The WPA2 four-way handshake is used to establish shared session keys between a wireless client and an access point. During this process, four EAPOL-Key messages are exchanged to confirm that both devices possess the required key material.

In this experiment, a supplied PCAP file was analyzed using Wireshark to identify all four handshake messages and examine their important parameters.

## Tools and Technologies

- **Wireshark:** For capturing and analyzing network packets.
- **PCAP File:** `Network_Join_Nokia_Mobile.pcap`
- **WPA2:** Wireless network security protocol.
- **EAPOL:** Extensible Authentication Protocol over LAN.
- **EAPOL-Key:** Key exchange messages used during the WPA2 handshake.

## Objectives

- Understand the WPA2 four-way handshake process.
- Identify all four EAPOL-Key messages.
- Examine ANonce and SNonce values.
- Analyze Message Integrity Code (MIC) values.
- Understand the purpose of replay counters.
- Identify communication between the access point and wireless client.
- Study the WPA Information Element and encryption parameters.

## Theory

The WPA2 four-way handshake establishes the Pairwise Transient Key (PTK) between a wireless client and an access point.

The process uses two nonces:

- **ANonce:** Random value generated by the access point.
- **SNonce:** Random value generated by the wireless client.

The handshake consists of four messages:

1. **Message 1:** The access point sends the ANonce to the client.
2. **Message 2:** The client generates and sends the SNonce along with a MIC.
3. **Message 3:** The access point sends the ANonce again with a MIC and key installation information.
4. **Message 4:** The client sends the final MIC to confirm successful key installation.

The MIC helps verify the integrity and authenticity of handshake messages. Replay counters help detect replayed or outdated messages.

### Step 1: Load the PCAP File

- Opened Wireshark.
- Loaded the supplied capture file:


- Examined the captured wireless network traffic.

### Step 2: Apply EAPOL Display Filter

Applied the following display filter to identify EAPOL packets:

```text
eapol
```

This displayed the packets related to the WPA2 authentication handshake.

### Step 3: Identify Four Handshake Messages

Located the four EAPOL-Key messages in the packet capture.

The following frames were selected for detailed analysis:

| Message | Frame Number |
|---|---|
| Message 1 | 726 |
| Message 2 | 728 |
| Message 3 | 733 |
| Message 4 | 738 |

### Step 4: Examine EAPOL-Key Parameters

Opened each selected packet and expanded:

```text
802.1X Authentication
    → Key Descriptor
```

Examined the following parameters:

- Key Information
- Nonce
- MIC
- Replay Counter
- Key Data Length

### Step 5: Analyze Communication Direction

Observed the communication between the wireless access point (Siemens AP) and the Nokia client.

Identified which messages were transmitted by the access point and which were sent by the client.

### Step 6: Verify Complete Handshake

- Confirmed the presence of all four EAPOL-Key messages.
- Compared the nonce and MIC values.
- Checked the replay counter sequence.
- Observed the WPA Information Element in Frame 728.

The information element indicated TKIP for the multicast and unicast cipher suites and PSK for authentication and key management.

## WPA2 Four-Way Handshake Flow

```text
             SIEMENS AP                 NOKIA CLIENT
                  |                           |
                  |                           |
                  |------ Message 1 --------->|
                  |       ANonce              |
                  |       Replay: 0           |
                  |                           |
                  |<----- Message 2 ----------|
                  |       SNonce + MIC        |
                  |       Replay: 0            |
                  |                           |
                  |------ Message 3 --------->|
                  |       ANonce + MIC        |
                  |       Replay: 1            |
                  |                           |
                  |<----- Message 4 ----------|
                  |       MIC                 |
                  |       Replay: 1            |
                  |                           |
                  |                           |
                  +--- Handshake Complete ----+
```

## Discussion

The Wireshark analysis confirmed the presence of all four messages involved in the WPA2 authentication handshake.

Message 1 contained the ANonce generated by the access point, while Message 2 contained the SNonce generated by the client along with a MIC.

Message 3 carried the ANonce again with a MIC, and Message 4 contained the final MIC to confirm the handshake.

The replay counters helped identify the sequence of messages exchanged between the devices. The analysis demonstrated how WPA2 uses nonces and MIC values to establish and verify session keys securely.
